# Audit: stack, edge cases and security hardening

Read-only audit of 24 Oct 2026: online research into the stack, a read-through of the backend and frontend, and probes of the live site (read-only requests). This file is the plan for fixing what it found.

Related: [feature-options.md](feature-options.md), [position-model.md](position-model.md), [legal-compliance.md](legal-compliance.md)

## 2. Already solid

- **Backend:**
  - responses serialised once and served with ETags;
  - the SSE stream drops slow clients instead of waiting on them, and caps total connections;
  - the static load backs off and retries, and `/healthz` fails when the data stops covering today.
- **Frontend:**
  - no HTML injection paths;
  - stored settings validated before use;
  - every `target="_blank"` link has `noopener`;
  - timers and listeners cleaned up;
  - malformed stream events ignored.
- **API cross-origin rules:** a foreign origin gets no CORS permission (tested live).
- **Data edge cases handled:**
  - DST nights;
  - the service day rolling over at 04:00;
  - previous-day RT times;
  - cancelled runs, duplicate GVB messages (KV15 + SIRI-GM), metro vehicle positions without GPS;
  - feed lag of 35–60 s;
  - predictions reaching only ~40 min ahead.

## 3. Findings

### High

**H1. The departures cache can fill the server's memory.**
- **The problem:** `/api/departures` caches every station × `limit` (1–60) × `minutes` (5–180) × `cancelled` combination: **823,680 possible keys**. Entries go only when the static subset changes (about daily). A full answer is ~14 KB, plus a gzipped copy.
- **Risk:** a script looping through the parameters can push the 512 MB instance into an out-of-memory crash.
- **Fix:**
  - bound the cache (LRU or size cap, like the journey cache);
  - drop expired entries;
  - snap `minutes` and `limit` to the values the app uses (15/30/60/120 and 8/60).

**H2. No limits per visitor.**
- **SSE:** `/api/trains/stream` allows 500 connections in total but none per client, so one script can take all 500 and every other visitor gets 503.
- **Journey planner:** its cache clears completely when full, so cycling station pairs keeps the 0.5-CPU instance busy.
- **Fix:**
  - a per-IP cap on SSE streams;
  - light per-IP rate limiting on the computed endpoints;
  - behind Render and Cloudflare the client IP comes from forwarded headers, so uvicorn must trust the proxy (`--proxy-headers`, `--forwarded-allow-ips`), or read `CF-Connecting-IP`.

### Medium

**M1. Missing security headers on the website.** The live site sends only `nosniff` and `Referrer-Policy`. Missing:
- **`Strict-Transport-Security`:** first visits can be downgraded to HTTP.
- **`Content-Security-Policy`:** no backstop against injected scripts. MapLibre needs `worker-src blob:`, `img-src data: blob:`, plus the OpenFreeMap and API origins. Roll it out as `Content-Security-Policy-Report-Only` first.
- **`X-Frame-Options: DENY` / `frame-ancestors 'none'`:** the page can be framed (clickjacking).
- **`Permissions-Policy`:** `geolocation=(self), camera=(), microphone=()` (the travel page uses geolocation).

The production services were created in the Render dashboard, which does not read `render.yaml`: set the headers there, and mirror them in `render.yaml`.

**M2. API docs are public.** `/docs`, `/redoc` and `/openapi.json` return 200 on the live API. Disable them in production (`docs_url=None`, `redoc_url=None`, `openapi_url=None`, behind an env flag).

**M3. Builds are not reproducible.**
- `backend/requirements.txt` has only `>=` floors and no lock file, so a deploy can install newer packages than CI tested.
- Render builds the frontend with `npm install`, not `npm ci`, so it may not follow `package-lock.json`.
- **Fix:** a pinned lock (e.g. `pip-compile`, or `requirements.lock` used by Render), and `npm ci` in the Render build command.

**M4. No WebGL context-loss handling.** Phones drop the GPU context of backgrounded apps, and nothing listens for `webglcontextlost`/`webglcontextrestored`, so the deck.gl layer may stay blank until reload. First reproduce it on a phone (or with `WEBGL_lose_context`), then handle it.

**M5. Stale data shown as live during an OVapi outage.** Fixed in PR #142 (open, all checks green).

### Low

- **L1.** The map's zoom/compass labels keep the language the page loaded in; MapLibre reads its locale only at construction.
- **L2.** If `/api/alerts` fails on first load (e.g. mid-deploy), the client waits a full 2-minute poll before retrying.
- **L3.** Cloudflare caches the entry page for 5 minutes (`s-maxage=300`): a deploy can take up to 5 minutes to show. Known; fine.
- **L4. Test gaps:**
  - no test that caches stay bounded;
  - no end-to-end browser test of the real map;
  - reduced motion and an OVapi outage never checked by eye.
